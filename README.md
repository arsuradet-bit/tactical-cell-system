# INTEL — ศูนย์วิเคราะห์พิกัด

> **รุ่นปรับปรุง 14/09/2026:** ข้อกำหนดปัจจุบันอยู่ใน `ALL_POINTS.md` และแทนที่แนวทางเลือกจุดล่าสุด/ตัดซ้ำด้านล่าง เว็บใช้ `survey_database.py` อ่าน `gmon_survey_logs` ทุกแถวร่วมกับ `intel_gmon_uploads` แบบเพิ่มอย่างเดียว ต้องรัน `schema_all_points.sql` ก่อนใช้งานรุ่นนี้ ตารางเก่าไม่ถูกลบหรือแก้ไข

เว็บ Streamlit ออกแบบใหม่สำหรับองค์กรขนาดเล็ก ใช้ PostgreSQL บน Cloud SQL และแผนที่ OpenStreetMap ผ่าน Folium

ติดตั้งบน Streamlit เดิมและย้ายข้อมูลแล้วเมื่อ 14 กันยายน 2026 ดูผลทดสอบและข้อจำกัดใน `VALIDATION.md` ขั้นตอนด้านล่างใช้สำหรับติดตั้งซ้ำหรือดูแลระบบ

## สิ่งที่ทำได้

- ค้นหา CELL/XCI, LAC/TAC หรือ xNBID อย่างใดอย่างหนึ่ง หรือร่วมกัน โดยเทียบรหัสตรงตัว
- หลายรหัสในช่องเดียวใช้จุลภาคคั่น (OR ภายในช่อง และ AND ระหว่างช่อง)
- เลือกพิกัดที่ใช้ได้ล่าสุดตาม DATE + TIME แยกตาม PLMN + XCI + LAC/TAC เก็บประวัติทั้งหมด
- ถ้าวันเวลาเท่ากัน คงจุดที่ได้รับเลือกไว้ก่อน ไม่ตัดสินว่าจุดไหนแม่นกว่าจากเวลาอัปโหลด
- ทุกคนที่เข้าสู่ระบบอัปโหลด G-Mon ได้ ตรวจหัวคอลัมน์ พิกัด วันเวลา และรายการซ้ำก่อนบันทึก
- รักษา PLMN จริง ไม่เขียนทับด้วยชื่อค่ายหรือรหัสหลายตัวรวมกัน
- CDR รองรับ CSV, TXT และ XLSX อ่านตามชื่อหัวคอลัมน์ จับคู่ Cell ID + LAC ใช้ G-Mon เป็นหลัก
- หากหา G-Mon ที่ใช้ได้ไม่พบ ใช้ Latitude/Longitude ของ CDR เป็นสำรอง หากฐานข้อมูลเชื่อมต่อไม่ได้ จะรายงานข้อผิดพลาด ไม่แกล้งรายงานว่าไม่พบข้อมูล
- ใช้ Start Date ของ CDR เรียงเวลา กรองเริ่ม/สิ้นสุด และเล่น/หยุด/เลื่อนลำดับเหตุการณ์บนแผนที่
- ถ้าพบหลาย PLMN แสดงผู้สมัครทุกเครือข่าย พร้อมคำเตือน ไม่เลือกเองและไม่ลากเส้นผ่านเหตุการณ์กำกวม
- วาด Sector จำลองเฉพาะเมื่อผู้ใช้กรอกทิศ (0°=เหนือ, 90°=ตะวันออก) ไม่ใช้ DELTA_AZI เป็นทิศเสา
- โหลด CELL อื่นร่วม PLMN/xNBID ได้ ไม่อ้างว่าเป็น Sector ที่ทราบทิศ
- ค้นหาพื้นที่ด้วยกรอบละติจูด/ลองจิจูด ยังไม่มีการค้นหาชื่อที่อยู่ผ่านบริการ geocoding

## ติดตั้งบน Streamlit เดิม

1. สำรองโค้ดเดิมใน GitHub เป็น branch หรือ tag ก่อนเปลี่ยน
2. นำไฟล์ในโฟลเดอร์นี้ขึ้น repository เดิม โดย `app.py`, `core.py`, `database.py`, `maps.py`, `style.css`, `fonts.css`, `requirements.txt` อยู่ระดับเดียวกัน และนำโฟลเดอร์ `.streamlit` ไปด้วย
3. ใน Streamlit Settings → Secrets ใช้โครงสร้างจาก `.streamlit/secrets.example.toml` กรอกข้อมูลจริงใน Secrets เท่านั้น ไม่ใส่ใน GitHub
4. ตั้งรหัสผ่านองค์กรใหม่และรหัสผ่านฐานข้อมูลใหม่ เนื่องจากฉบับเดิมฝังรหัสผ่านไว้ในซอร์ส อย่าใช้ค่า placeholder ในตัวอย่าง
5. ตรวจว่า Cloud SQL ยอมรับการเชื่อมต่อจากบริการที่รัน Streamlit และตั้งค่า TLS ตรงกับอินสแตนซ์ ตัวอย่างใช้ `sslmode=require`; หากต้องใช้ client certificate ให้ตั้งค่าเพิ่มตามตัวอย่าง การตั้ง firewall ไม่ใช่สิ่งที่โค้ดนี้เปลี่ยนให้อัตโนมัติ
6. ใน Cloud SQL Studio เลือกฐานข้อมูลที่ใช้งาน แล้วรัน `schema.sql` หนึ่งครั้งด้วยผู้มีสิทธิ์สร้างตาราง
7. หากใช้บัญชีฐานข้อมูลแยกจากผู้สร้างตาราง ให้ผู้ดูแลให้สิทธิ์ SELECT/INSERT กับ `intel_gmon_observations`, SELECT/INSERT/UPDATE กับ `intel_gmon_latest` และ USAGE/SELECT กับ sequence ของตารางแรก
8. ย้ายข้อมูลเดิมตามหัวข้อถัดไป หรืออัปโหลดไฟล์ G-Mon ต้นฉบับผ่านหน้าเว็บ
9. ให้ Streamlit ใช้ Python 3.12 และ entry point `app.py` จากนั้นทดสอบการค้นหาและนำเข้าในระบบจริง

ตารางใหม่คือ `intel_gmon_observations` (ประวัติ) และ `intel_gmon_latest` (ตัวชี้จุดล่าสุดพร้อมดัชนี) โค้ดนี้ไม่แก้หรือลบ `gmon_survey_logs` เดิม และจะยังไม่เห็นข้อมูลเดิมจนกว่าจะย้ายข้อมูลหรือนำเข้าใหม่

## ย้าย G-Mon จากตารางเดิม

ดำเนินการบนเครื่องผู้ดูแลที่เชื่อมฐานข้อมูลได้ มี Python 3.12 และติดตั้ง requirements แล้ว

สร้าง `.streamlit/secrets.toml` บนเครื่องจากไฟล์ตัวอย่าง โดยไม่ commit ไฟล์จริง จากนั้น:

```sh
python migrate_legacy.py
```

คำสั่งนี้ตรวจโครงสร้างและจำนวนแถวที่ใช้ได้เท่านั้น ไม่เขียนข้อมูล หากผลตรวจถูกต้องและสร้างตารางใหม่แล้ว:

```sh
python migrate_legacy.py --apply
```

การย้ายเขียนตารางใหม่เป็นชุดและรันซ้ำได้โดยตรวจรายการซ้ำ หากหยุดกลางทาง รันซ้ำได้ ตารางเดิมไม่เปลี่ยน แถวผิดรูปแบบยังอยู่ในตารางเดิม หากไม่มีคอลัมน์ที่ต้องใช้ เช่น PLMN, DATE หรือ TIME ต้องตรวจข้อมูลเดิมก่อน ไม่อนุมานรหัสค่ายจากข้อความรวมใน network_code

## CDR ชั่วคราว

- ไม่เขียน CDR ลงฐานข้อมูล ไฟล์ดิสก์ Cloud Storage หรือ cache ส่วนกลาง
- ไม่เก็บ Number A/B, IMSI หรือ IMEI ในข้อมูลวิเคราะห์ที่แปลงแล้ว
- ไฟล์ต้นฉบับอยู่ในหน่วยความจำของ file uploader ขณะเซสชันใช้งานอยู่
- กด “ล้างไฟล์และผล CDR” เพื่อล้างผลและรีเซ็ต uploader หรือออกจากระบบเพื่อล้างสถานะเซสชัน
- การปิดแท็บอาศัยวงจรจัดการเซสชันของ Streamlit ไม่ใช่การรับประกันว่าหน่วยความจำถูกเขียนทับทันที ใช้ปุ่มล้างก่อนเลิกงาน
- เวลาในไฟล์ตีความเป็นเวลาท้องถิ่นประเทศไทย ไม่มีการแปลงเขตเวลาอัตโนมัติ รองรับปี ค.ศ./พ.ศ. 4 หลัก
- เส้นไทม์ไลน์ใช้ Start Date ไม่ใช้ End Date หรือ Quantity คำนวณการพักอยู่ในพื้นที่
- ภาพพื้นหลัง OpenStreetMap โหลดจากผู้ให้บริการแผนที่ภายนอก ผู้ให้บริการได้รับคำขอ tile ตามพื้นที่ที่เปิดดู ไม่ได้รับไฟล์ CDR จากโค้ดนี้

## ทดสอบและข้อจำกัด

```sh
pip install -r requirements.txt
python -m unittest -v test_core.py
streamlit run app.py
```

โหมดตรวจหน้าตา: ตั้ง environment variable `INTEL_DEMO=1` ก่อนรัน ใช้ข้อมูลสังเคราะห์และปิดการเขียนฐานข้อมูล **ห้ามตั้งค่านี้บนเว็บใช้งานจริง** เพราะโหมดนี้ข้ามหน้าเข้าสู่ระบบเพื่อแสดงตัวอย่าง

ผลทดสอบของชุดส่งมอบอยู่ใน `VALIDATION.md` ทดสอบ Cloud SQL จริงแล้ว ยังต้องทดสอบกับไฟล์ CSV/CDR ต้นฉบับจริงและผู้ใช้พร้อมกัน 10–15 คนก่อนรับรองสมรรถนะ

ข้อจำกัดที่ตั้งใจไว้: อัปโหลดไม่เกิน 20 MB/ไฟล์, อ่านไม่เกิน 100,000 แถว/ไฟล์, วิเคราะห์ไม่เกิน 5,000 เหตุการณ์ CDR ต่อครั้ง และค้นหาแผนที่ไม่เกิน 2,000 จุดต่อครั้ง โดยมีข้อความแจ้งเมื่อเกินขอบเขต ไม่มีการล้างหรือส่งออก CDR อัตโนมัติเป็นไฟล์ ไม่มีโมดูลคัดกรองรถในฉบับนี้
